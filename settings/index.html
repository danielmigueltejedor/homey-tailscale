Connection

Basic settings to authenticate Homey on Tailscale and how it appears on the tailnet.

Use a reusable or ephemeral auth key from the Tailscale admin console. It is never printed in logs.
Name this node will use on the tailnet.
Optional. Comma-separated Tailscale tags for grants-based ACLs, e.g. tag:homey,tag:mehet-budapestre. Must be allowed for your auth key.
This app runs Tailscale in userspace networking mode (required inside Homey). Peer-to-peer access to Homey's Tailscale IP works. Kernel route installation is not available (fakeRouter.Set: not implemented in logs is expected). Enable Accept routes and check “Accepted subnet routes” after reconnecting.

Subnet router (advanced)

Optionally advertise local subnets from this Homey. Prefer a dedicated subnet router (NAS/PC) when you need reliable LAN access for other nodes.

Userspace mode cannot install kernel routes or do full LAN forwarding like a normal Tailscale subnet router. Advertising from Homey is experimental — other nodes may not reliably reach your LAN through Homey. Reaching Homey itself via its 100.x IP is the supported use case.
CIDR format. Separate multiple with commas. Example: 192.168.1.0/24,192.168.50.0/24
